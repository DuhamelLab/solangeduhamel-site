## 1. Make the router crash-proof and add tab deep links

**Status:** proposed · **Effort:** S · **Category:** robustness / sharing · **Sources:** E1 (score 8–9 from all critics)

**Why:** A malformed or truncated pasted link such as `#%E0%A4%A` throws a URIError at app.js:70 and `route()` (app.js:433) is outside any `safely()` wrapper, so the page can render nothing. Filter params are unvalidated (`tag=foo`, `year=abc`), and tab state never reaches the URL, so a journalist or committee cannot link to Alumni, Preprints or Media.

**What:** try/catch around the decode with a fall-back to Home; whitelist `tag` against the chip vocabulary and coerce `year` to a valid integer; support `#team?tab=alumni`, `#opportunities?tab=teaching`, `#data?tab=media`, `#publications?tab=preprints`. Selecting a tab from the URL must update `aria-selected` and roving tabindex without stealing focus. Tab deep links are the optional second half.

**Implementation:** js/app.js only (`parseHash`, `route`, `initTablist`, `applyPubParams`). Test with malformed hashes, Back/Forward, and keyboard tab use.

**Panel concerns addressed:** Perf critic: split the deep links off as optional. A11y critic: no focus stealing, keep ARIA state in sync.

## 2. Close the schema gap between data.js, the validator and the renderer (and keep the sitemap fresh)

**Status:** proposed · **Effort:** S · **Category:** bot safety / maintainability · **Sources:** E3 (score 7–8)

**Why:** `feature` and `short` change what the Home page shows (app.js:199, 201) but appear in neither the data.js header nor scripts/validate-data.mjs. sitemap.xml `lastmod` is 7 months behind `lastUpdated`. Duplicate titles are not detected.

**What:** Document and validate `feature` (boolean) and `short` (string); error on duplicate normalised titles; warn when `y` disagrees with `n` order; make the weekly routine copy `lastUpdated` into sitemap.xml `<lastmod>` (or warn in CI when they differ by more than 30 days). Skip the author-regex and first-tag checks unless a real incident justifies them (perf critic: bot-PR noise).

**Implementation:** scripts/validate-data.mjs, header comment in js/data.js, one line in the weekly routine instructions, a one-time sitemap fix.

**Panel concerns addressed:** Keeps validator strict only where the renderer actually depends on the field.

## 3. Cut phone paint cost and add a portrait pause

**Status:** proposed · **Effort:** S · **Category:** performance / accessibility · **Sources:** E4, a11y critic (WCAG 2.2.2)

**Why:** `background-attachment:fixed` on four gradients (style.css:48) and a fixed full-viewport feTurbulence grain layer (style.css:51-55) force repaints while scrolling on Chromium phones, and iOS ignores `fixed` anyway. The 20 s portrait swap (app.js:149-155) sets `src` and shows it 400 ms later with no preload, so the first swap can flash. An auto-updating image with no pause control is an open 2.2.2 question.

**What:** Move the gradients to a non-fixed pseudo-element or static background; replace the SVG grain with a tiny pre-rendered tile or remove it; preload with `new Image().decode()` before swapping; add a small pause/play control (or stop cycling after N swaps). Keep the existing reduced-motion and hidden-tab guards. Measure a throttled mid-tier phone trace before and after; delete dead CSS only after confirming it is unused.

**Implementation:** css/style.css (body, `body::after`), js/app.js (portrait interval), a small button in index.html.

**Panel concerns addressed:** "Drop will-change" and "delete 60 lines" demoted to measure-first.

## 4. Complete social/SEO metadata and add persistent identifiers

**Status:** proposed · **Effort:** S · **Category:** findability · **Sources:** E6, S4

**Why:** No `og:image:alt`, `twitter:image`, `og:site_name` or `og:locale` (index.html:17-29); 404.html has no `noindex`; images/gallery-2.webp is unreferenced; JSON-LD `sameAs` (index.html:46) has only ORCID and Scholar.

**What:** Add the missing meta tags with a descriptive alt for the og-card; `noindex` on 404; delete unreferenced images (or wire them in with distinct alt text); add OpenAlex author ID, Scopus ID and ROR for the University of Arizona to `sameAs` **only after the PI supplies/confirms the IDs**. Dropped: bot-synced JSON-LD articles and `rel=me`.

**Implementation:** index.html head, 404.html, image deletions.

**Panel concerns addressed:** Chair/perf critics: no new bot logic.

## 5. Light up "Selected publications": draft the "why" sentences for the PI

**Why:** The feature shipped on 2026-11-13 but no entry has `key:true`/`why`, so the section is hidden (`wrap.hidden`, app.js:238) and the site's best curation signal is invisible to panels and recruits.

Nothing is added to data.js without her sign-off; `key` and `why` stay hers. Optionally let Home "Latest Work" prefer `key` items only if it does not conflict with the derived list (check first).

**Implementation:** a draft file; later `key:true, why:"…"` on ~6 pubs in js/data.js; documented via #2.

**Panel concerns addressed:** No fabricated claims; PI approves every sentence.

## 6. Team page roster-first (demote the 760 px group photo)

**Status:** proposed · **Effort:** S · **Category:** layout / accessibility · **Sources:** D4

**Why:** The Team banner is `height:min(760px,calc(var(--nav-h) + 75vw))` (index.html:322) with the photo as a CSS background (no alt text), so on desktop about 800 px of the first screen is a photo and the roster sits below the fold.

**What:** Use the standard banner height, and place the group photo as a real `<figure><img alt>` with a PI-written caption (people, year), width/height attributes and `loading=lazy`. Minimum alternative (perf critic): just cap the banner height on phones.

**Implementation:** index.html:322-329; a few lines of style.css.

**Panel concerns addressed:** Meaningful alt text and caption need the PI's input.

## 7. CSS-only typographic refinement

**Status:** proposed · **Effort:** S · **Category:** typography · **Sources:** D5

**Why:** style.css has no `text-wrap` or `tabular-nums`, so card titles can orphan a word and year columns, histogram ticks and counts wobble; paragraphs in cards run to ~85 characters at 1080 px.

**What:** `text-wrap:balance` on headings/card titles and `pretty` on paragraphs; `font-variant-numeric:tabular-nums` on year heads, team years, histogram ticks, metrics; `max-width:68ch` on prose blocks. **Dropped:** fluid type tokens (churn). Any clamp must be rem-based so text zoom still works (WCAG 1.4.4). Check at 360, 768, 1080 px and at 400% zoom.

**Implementation:** one block in css/style.css.

## 8. About page: appointments and education as a semantic CV list

**Status:** proposed · **Effort:** S · **Category:** layout / semantics · **Sources:** D2 (score 6–8)

**Why:** index.html:199-224 is about 25 inline-styled `<p>` tags with ragged trailing years.

**What:** A `<dl>` (or `<ul>`) with a mono year column and role/institution text; stack year above role on phones; real headings in place of the `.tag-label` paragraphs; years at least 14 px; "Current" visually heavier. Markup only; data stays in HTML (a data-driven version, E5, was deferred).

**Implementation:** index.html:199-224 and ~10 lines of CSS. Removes inline styles, a step toward a tighter CSP later.

## 9. Phone-first publications layout (revised, no hidden filters)

**Status:** proposed · **Effort:** M · **Category:** mobile UX · **Sources:** D3 (revised)

**Why:** On a 390 px screen the Selected block, search, metrics, Scholar link, wrapped chips, count and histogram stack before the first citation (index.html:279-302; style.css:321). Chips are 36 px on fine pointers (style.css:354).

**What:** At ≤700 px: put the (currently empty) Selected block below the search or collapse it; present chips as a single horizontally scrolling row with a visible fade; chips ≥44 px on coarse pointers; keep the count visible. **No `<details>` that hides filters and no sticky bar** (critics: extra tap, hurts discoverability, WCAG 2.4.11 focus-obscured risk with the fixed nav, iOS keyboard issues). If anything is sticky, only the search, with `scroll-margin-top` covering nav plus bar.

**Implementation:** css/style.css media query; minor markup order change in index.html; no change to filter state logic in app.js.

## 10. Alumni "Now at" line (optional, PI-supplied only)

**Status:** proposed · **Effort:** S–M · **Category:** recruiting credibility · **Sources:** S1 (score 7, 7, 4)

**Why:** Prospective students and committees judge a mentor by trainee outcomes; alumni rows list years, degree and topic only (index.html Team section).

**What:** An optional italic line, plain text with an optional link, shown only where the PI supplies it ("Now: Postdoc, X University"). No derived summary counts (staleness/vanity concern) and no invented placements. Privacy: the PI confirms each person is happy to be listed. Keep team markup in HTML for now; move to data.js only if the PI later wants the bot to maintain it (deferred E5).

**Implementation:** index.html alumni rows plus one CSS class.
