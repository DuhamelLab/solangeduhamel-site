## 1. Make hash navigation behave like real navigation (Back button, title, focus, main landmark)

**Status:** proposed · **Effort:** S · **Category:** accessibility / correctness · **Sources:** E2, D8 (h1 promotion), S12(2)

**Why:** On phones the Back gesture currently leaves the site, the skip link points at an empty element, and screen-reader users get no signal that the page changed. This is a bug every visitor runs into.

**What:** (a) Remove the preventDefault + history.replaceState click handler (index.html:521). Plain <a href="#research"> links plus the existing hashchange listener give correct back/forward behaviour. Keep a click handler only to close the mobile menu. (b) Replace the empty <div id="main-content" role="main"> (index.html:75) with <main id="main-content" tabindex="-1"> wrapping all .page divs. (c) In showPage(): set document.title from a map such as 'Publications — Solange Duhamel', and turn each page banner's heading into an h1 (the hero h1 stays on Home). After a navigation (not on first load), focus that h1 with tabindex=-1 and {preventScroll:true}. Use focus as the only announcement and add no aria-live region, so VoiceOver does not read the page name twice. (d) Send unknown hashes to #home instead of blanking the page. Close and reset the mobile menu before moving focus.

**Implementation:** index.html only: the markup around lines 75 and 76-450 (wrap the pages in <main>, change banner h2 to h1 with the same class so the CSS is unchanged), and showPage/handleHash plus the click handler around lines 494-525. Add a subtle :focus-visible rule for the h1 in css/style.css. Test Back/Forward and swipe-back on iOS Safari, deep links (#publications), and that #foo falls back to Home.

**Panel concerns addressed:** Avoids the double announcement from focus plus a live region (a11y critic). Keeps the menu-close handler, which is the only legitimate reason the preventDefault handler existed (perf critic). Merges the D8 and S12 title/h1 work, so showPage is touched once.

## 2. Guard the weekly bot: data.js validator in CI, render try/catch, computed counts, link check, documented schema

**Status:** proposed · **Effort:** M · **Category:** reliability / maintainability · **Sources:** E10, critic (try/catch, schema doc, link-rot check, perf budget)

**Why:** A bot rewrites executable code every week, and one malformed entry (for example a missing tags array) currently blanks every list on the site. This is the single safeguard that protects every other improvement.

**What:** 1) Wrap each render* call in initSite (index.html:558-573) in its own try/catch. On failure, show a visible fallback ('This list failed to load — see Google Scholar/ORCID') instead of an empty region, and guard optional fields (p.tags||[]). 2) Add .github/workflows/validate.yml running scripts/validate-data.mjs on every PR. It evaluates data.js in node:vm with an appended ';({pubs,preprints,bookChapters,outreach,datasets,media,activeProjects,completedProjects})' (a top-level const is not visible on the vm context otherwise) and checks: y in 1990..currentYear+1; non-empty t/a/j; tags drawn only from the chip vocabulary; unique DOIs matching ^10\.\d{4,9}/\S+$ with no doi.org prefix; unique n; every URL https; and the optional fields listed below are well-formed when present. 3) Add a weekly and per-PR link/DOI check (lychee) in the same workflow, reported but not blocking at first. 4) Add a size budget that fails if any images/*.webp exceeds 250 KB. 5) Replace every hard-coded count with values computed from the arrays ('Showing 70 publications' at index.html:289 is wrong; there are 73 pubs). 6) Put one schema header comment at the top of data.js listing every allowed optional field (key, why, oa, award, dois, data, publishedDoi, metrics, openings), so later proposals do not each invent their own format. Require the check through branch protection. Leave out the automatic PR-comment diff and any Scholar scraping.

**Implementation:** New files .github/workflows/validate.yml and scripts/validate-data.mjs (about 80 lines, no dependencies). Edit index.html initSite and the count elements, and add the header comment to js/data.js. Note: Node is not installed on this Mac, so the check runs only in GitHub Actions. Add a short README note for the PI on reading a failed check.

**Panel concerns addressed:** Includes the vm const gotcha fix (perf critic). Rules are per array and not overly strict, so legitimate PRs are not blocked. The visible fallback message replaces a silent blank (a11y critic). Scholar scraping is dropped as against Scholar's terms of service; the link checker is added (credibility critic). The single schema comment answers the 'every proposal invents a field' concern.

(5) Give every <img> width/height (index.html:94, 149, 185, 438-440) and loading=lazy below the fold, and use the existing but unused images/sm/ variants as srcset for the gallery. (6) Recompress research-banner (401 KB), data-banner (448 KB) and team-banner (306 KB) to about 120-150 KB at 1600w. Replace teaching-bg (357 KB, shown at opacity 0.06) with a CSS gradient. (7) Reserve min-height on the list containers to avoid layout shift (CLS). Record Lighthouse figures before and after.

**Implementation:** index.html: the hero markup, the load listener and the img attributes. css/style.css: hero sizing, chip wrapping, phone order. **Status:** proposed · **Effort:** M · **Category:** data visualization / accessibility · **Sources:** D6 (critic-revised)

**Why:** The current bar chart reveals values only on hover (style.css:200-201), so touch and keyboard users never see them. It has no axis and no text alternative, and .chart-year-label is defined but never output.

**What:** An inline SVG in a single colour (no theme stacking, no cumulative line). Bars per year, decade ticks (2005…2025) and a max-count label, all text at 12px or more. role=img with an aria-label summary ('Publications per year, 2004–2026, peak N in YYYY'), plus a <details> 'Show data table'. Year filtering uses real <button> elements laid over the columns with hit areas at least 44px tall, setting the shared year filter from #14, with a visible 'Clear' chip. No entrance animation.

**Implementation:** The index.html/app.js chart renderer replaces the div bars. CSS for the axis and buttons. Depends on #14's state object.

**Panel concerns addressed:** Drops the stacked colour-only encoding, the dual-axis 'vanity' line and the animation (all critics). Uses real buttons instead of role=button on <g> elements, which VoiceOver supports poorly. Includes a table alternative.

## 19. Link research projects to their awards, papers and datasets

**Status:** proposed · **Effort:** M · **Category:** content / funders · **Sources:** S6

**Why:** NSF and NASA program officers look for the outcomes of each award. The data already exists in data.js but is not connected.

**What:** Optional fields on projects: award (an ID rendered as a link to the NSF award search), dois:[…] and data:[accessions]. Each card gets an 'Outcomes: n papers · m datasets' <details> that resolves the DOIs against pubs and the accessions against datasets, plus a 'See all related papers' link using #14's hash parameters. The four Home highlight cards link to the filtered publications. Award IDs are entered by hand or proposed only in the bot's PR description for the PI to approve. The validator checks that every listed DOI exists in pubs, and lychee checks the award URLs.

**Implementation:** js/data.js (optional fields on activeProjects and completedProjects), the project renderer in index.html/app.js, validator rules.

**Panel concerns addressed:** Human verification of award IDs. The bot only suggests links (all critics). Uses <details> for disclosure (a11y). Link-checked for URL drift.

## 20. Open-access 'Free to read' links precomputed weekly into data.js

**Status:** proposed · **Effort:** M · **Category:** content / public reach · **Sources:** S2

**Why:** Students, journalists and readers outside the US often cannot get past paywalls. A verified free-to-read link opens the work to them without any runtime tracking.

**What:** An optional oa field holding an https landing-page URL (not a pdf_url), filled weekly by the agent from OpenAlex best_oa_location and rechecked each week. Render a text pill 'Free to read' next to the DOI link, not inside it, add an 'Open access' chip, and show 'X of N freely readable' in the summary. No oaType and no auto-opened repository-deposit issues; at most a list of paywalled papers in a quarterly PR description.

**Implementation:** js/data.js optional field, the renderPubList pill and chip, a validator rule (https), lychee coverage, and an update to the weekly agent's instructions.

**Panel concerns addressed:** Landing pages instead of brittle PDF links, link-checked weekly (credibility and perf critics). A text label, not colour (a11y). The bot's scope creep is removed.

## Rejected or deferred by the panel

- **E11 Offline-capable PWA with service worker** — Rejected by all three critics (scores 2-3). A cache-first service worker on a weekly-updated site risks serving stale openings and publications to committees and applicants, and it adds a cache-version rule the bot has to bump. No audience installs a professor's site as an app, and the GitHub Pages max-age=600 caching is adequate.
- **E3 Pre-rendered section URLs via a GitHub Action build and deploy-pages** — Deferred. It adds a build and changes the Pages source, which is exactly what the constraints warn against, and a failed Action would silently freeze the site while the bot believes it is updating it. #1 (router) and #5 (JSON-LD) deliver most of the benefit. Revisit only if search data shows a need, and then with bot-written static stubs or a CI step that keeps the last good deploy.
- **S7 Field-sites world map (inline SVG with pins and cruise tracks)** — 30-60 KB of map paths and a new coordinate data structure to show about 10 pins. It is inaccessible by default, needs a separate list on phones anyway, and raises permit and coordinate-accuracy issues. If storytelling is wanted, a 'Where we work' list with the existing gallery photos is better.
- **D10 Agent-drawn scientific SVG illustrations for the highlight cards** — A wrong PO4 geometry or a cartoon salamander-and-algae image would be spotted at once by the experts the site is courting. Only the <details> swap survives, inside #6. Equalize card heights with layout, or use the lab's own photos or published figures with credit.
- **D1 Six-hue research-theme colour system** — Deferred. It encodes a taxonomy the data does not have (no pub carries a 'symbiosis' tag, and 'marine' is a catch-all), the cyan and cerulean themes are nearly indistinguishable, and it carries meaning by colour alone (WCAG 1.4.1). It also adds a tag-precedence rule for the bot. It may return later as 3-4 tints on tag pills only, computed in render code, with the text labels kept.
- **D12 parts 2 and 5: scroll-driven section reveals and a pointer-tracked 'bioluminescent' glow** — Adds motion to reading content and a pointermove listener while #10 is cutting main-thread work. Content that starts at opacity 0 can stay invisible if the timeline misfires (print, reader view). This is the agency-portfolio look that lowers academic credibility.
- **D8 View Transitions and the sliding nav-underline morph** — Polish that adds code paths inside showPage, the function #1 has to fix, and it can fight the focus moving to the h1. The banner-token and h1 parts are absorbed into #1 and #7. Revisit only as a reduced-motion-gated 3-line enhancement after #1 has been verified.
- **D9 full-height Cormorant 34px menu sheet, stagger animation and scroll-snap tab row** — Design theatre for a six-item menu. A full-viewport backdrop blur is costly on mid-range phones, and a scroll-snap tab row hides tabs from zoomed users. The accessibility work is kept in #6 with a solid panel and 2x2 or short-label tabs.
- **D11 SVG 'lab lineage' tenure timeline with monogram discs** — Effort L. It is a heavy accessibility burden, invites comparisons of how long trainees took, and the monograms look like placeholders. Deferred in favour of the S9 team migration in a later pulse (semantic list, award chips with '+N more', alumni 'now' entries only with consent).
- **S9 automatic trainee underlining by surname-prefix matching (and replacing the manual 'student' tag)** — Surname matching produces false positives on a page committees read as a record of mentorship, and an underline alone conflicts with link styling and is invisible to screen readers. The team-to-data.js migration is a candidate for a coming week's pulse, with explicit per-pub trainee lists reviewed by the PI.
- **D2 phase 2: switching list titles from Cormorant to sans-serif** — A change to the brand voice that is the PI's decision, not a token cleanup. It needs screenshots at 375 and 1440px for PI approval before it is considered. The safe phase-1 typography fixes are in #7.
- **S1 per-row Cite popovers, RIS export and COinS spans** — Deferred. A popover on each of 73 rows is the hardest keyboard and touch pattern to get right for a narrow audience, and COinS is a dead format. A bulk 'Export these N as .bib' built locally is a good candidate for a later weekly pulse.
- **S5 news array and bot-generated Atom feed** — Cadence commitments a solo PI may not keep, and stale news looks worse than none. Bot-written XML is one more artifact to keep valid. Only the latestItems derivation ships (#12).
- **S12(4) bot-maintained <noscript> publication list inside index.html** — It gives the weekly bot write access to the main page file, which widens what it can break, the opposite of #2's goal. The useful parts of S12 are absorbed into #1, #5 and #14.
- **E10 optional automated Google Scholar metrics refresh** — Scraping Scholar is fragile and against its terms of service. The metrics are hand-entered with an asOf date and a staleness flag instead (#3).
- **S11 bot expansion of BCO-DMO and ReDATA aggregates into about 35 DataCite entries** — Risks wrong attributions under the PI's name from unsupervised queries, and it bloats a rarely visited tab. Optional doi/type/paper fields and a 'Data' pill are a candidate for a later pulse, with expansion only through PI-approved PRs.
- **S10 print-resolution press JPGs and repo-hosted CV PDF** — Deferred. Large JPGs bloat the repo and deploy, and a CV PDF goes stale or leaks details unless the PI commits to it. A short press section (bios in data.js, 1-2 approved headshots of about 1600px, a UA media contact) is a reasonable later-pulse item.
- **E12(a) GoatCounter analytics** — Not rejected on its merits, but it is a PI decision with a privacy-note and CSP impact. The public placeholder tab is removed now (#3). Stats, if adopted, should be viewed privately on goatcounter.com, not on the CV-facing site.

Batch 1, quick wins (all S, mostly independent, about one sitting): #2 part 1 only (try/catch per renderer + guarding p.tags + computed counts), #1 router/main/title/focus, #3 content accuracy + removing the Analytics tab + dated metrics, #5 valid JSON-LD, #8 recruiting copy + mailto links.
